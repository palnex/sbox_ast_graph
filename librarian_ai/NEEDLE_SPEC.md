# Технічна специфікація моделі Needle 26M (Cactus Compute)

**Needle** — це спеціалізована відкрита ШІ-модель надмалого розміру, дистильована з сімейства моделей **Google Gemini 3.1** (Gemini 3.1 Flash Lite) та оптимізована для високошвидкісного однопрохідного виклику функцій (Single-Shot Function Calling) на мобільних та Edge-пристроях.

---

## 1. Архітектурні параметри (Simple Attention Network)

Модель побудована за унікальним принципом **Simple Attention Network (SAN)**. 
Головна особливість — **повна відсутність повнозв'язних шарів (FFN / MLP)**. Модель не містить класичних шарів, які відповідають за збереження "знань про світ", оскільки для парсингу JSON вони є надлишковими. Модель використовує виключно механізми уваги (gating та attention).

* **Кількість параметрів:** 26,315,421 (26 мільйонів).
* **Розмір ваг на диску (FP16 / BF16):** ~52.5 MB.
* **Розмір ваг під час квантування INT4:** ~14 MB.
* **Шари енкодера (Encoder):** 12 шарів без FFN (Grouped-Query Attention (GQA), RoPE, Gated Residuals).
* **Шари декодера (Decoder):** 8 шарів з Masked Self-Attention + Cross-Attention.
* **Прихована розмірність ($d_{model}$):** 512.
* **Кількість голів уваги (Heads):** 8 голів для Query, 4 голови для Key-Value (GQA).
* **Розмір словника (Vocab Size):** 8,192 токени (BPE токенізатор SentencePiece).
* **Ліцензія:** MIT.

---

## 2. Параметри контексту та обмеження токенів

При роботі з моделлю Needle необхідно враховувати жорсткі межі контекстного вікна для стабільної генерації JSON:

* **Максимальна довжина входу (Контекстне вікно енкодера):** **1024 токени** (`max_enc_len`). Сюди входить сумарна довжина запиту користувача (Query) та JSON-схем доступних інструментів (Tools).
* **Максимальна довжина виходу декодера:** **96 токенів** (`max_new_tokens`). Оскільки вихідним результатом є короткий структурований JSON-рядок, ліміту у 96 токенів із запасом вистачає для повернення однієї або двох витягнутих функцій.
* **Обмеження міркувань (Zero general knowledge):** Модель не має загальних знань про світ. Вона не вміє вести діалог, рахувати математику або писати есе. Спроба спілкуватися з нею в режимі чат-бота призведе до генерації некоректного JSON.

---

## 3. Навчання та дистиляція

* **Pre-training:** Попереднє навчання на корпусі з **200 мільярдів токенів** (200B) на 16 процесорах TPU v6e протягом 27 годин.
* **Post-training (Fine-tuning):** Тонке налаштування на **2 мільярдах токенів** (2B) синтетичних даних виклику функцій (згенерованих через Gemini 3.1) за 15 категоріями (розумний дім, таймери, медіа тощо) за 45 хвилин.

---

## 4. Продуктивність (Inference Speed)

Під час запуску на рідному рушії виконання **Cactus Engine** (на мобільних процесорах чи ПК):
* **Prefill Speed (обробка промпту):** ~6000 токенів на секунду.
* **Decode Speed (генерація JSON):** ~1200 токенів на секунду.
* **Середня затримка на CPU при роботі через ONNX Runtime:** 120–400 мілісекунд на один запит (sub-400ms).
